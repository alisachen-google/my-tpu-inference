# Branch validation on the latest commits (2026-10-27)

Live 1P/1D validation of `alisachen-google/sglang-torchtpu:pd-victim-prefix-cache`
at its tip (200a2887, the switch-only configuration) on gpt-oss-120b, 128k+8k,
with the cache wiped before every point. Unit tests at the tip pass (391 in the
PD/raiden suites). The live run found the defects below; each fix lives in
`sglang_tpu/` only (no core files) and is committed as bb57d8a5 on the fork
branch `pd-spill-verification` together with its unit tests.

| # | Symptom seen live | Cause | Fix | Verified |
|---|---|---|---|---|
| 1 | Decode scheduler exits on the flush between points: `Cannot reset KV memory while host prefix offers are pinned` | The decode's idle check does not count offered or landing prefix pages the transfer queue still owns, so the flush proceeds into the cache reset while a prefill read is outstanding | Wrap `Scheduler.is_fully_idle` in `pd_victim_push.py`: a decode that owns such pages reports busy, the flush is refused and retried like any pending work | 3 unit tests; live: decode survives every flush |
| 2 | Recalls from decode RAM abandoned (`no_memory`), hit rate 42 to 52% instead of 59%; the decode's registrations for them expire after the deadline | A recall lands in the prefill's RAM; under write-through that RAM is full of copies of pages still in HBM, which host eviction never takes (host-only leaves only) | In `pd_host_prefix_recall.py`, when host eviction comes up short, reclaim FULL host copies of pages the device still holds, oldest first (the HBM copy stays, re-backed-up on its next demote) | 2 unit tests; live: 131k-token recalls complete in 0.7 to 1.0 s, no abandons |
| 3 | A push the decode refuses keeps the prefill "not idle" for the whole native deadline (10 min with `SGLANG_RAIDEN_TIMEOUT_S=600`) | The push's host pages are registered for the read before the offer; tpu-sync 759530c7 cannot cancel a registration | Recipes use the 60 s default chunk deadline; a code fix (register only after the decode accepts) is noted, not applied | Flush succeeds after the deadline |
| 4 | Prefill exits after a few recalls: `KeyError` in `evict_device_leaf` during the device eviction that makes room for a recalled prefix's load-back | Reclaiming a host copy for a recall landing leaves a device leaf without a backup; write-through eviction deletes such a leaf outright, and the FULL walk can yield it a second time in the same walk (once from its start-of-walk snapshot, once as the parent of a leaf taken later), where the lookup of the deleted node raises | The reclaim takes only childless duplicates, least recently used first (a later deletion never orphans a host-only subtree); a wrapper of the cache's `_evict_device_leaf` skips a node no longer in the tree, ending that step without a free | 2 unit tests; found by a node-removal tracer in the plugin's eviction wrapper over four live runs (three identical crashes) |
| 5 | After widening the reclaim to nodes with device children (for more host room), a recall landing's host insert raised `write-through host-prefix invariant broken: encountered backed node below a refilled host tombstone` and the prefill exited | Under write-through, host copies must stay closed under ancestors; reclaiming an internal node's copy while a child still had one left a host tombstone above a backed node | Reclaim a node's copy only while every child of it is device-only, so a chain is taken from its tip upward (commit 02380006); with that, the 12-doc static point reached 59.6% hit (our reference tree: 58.9%) with no abandoned recalls | 1 unit test (tip-first order); live run 7 pending |

## Transfer correctness (byte level)

A diagnostic build logs a CRC32 over every layer of each transferred page
set, in order, on both roles: for a push at the prefill's registration and
at the decode's landing, for a recall at the decode's read registration and
at the prefill's landing (`SGLANG_TPU_DEBUG_VICTIM_CRC=1`; join with
`harness/crc_compare_p1.py`). Run `p1crc_after_1` (branch tip, 12-doc static
and 12-session recall points, gpt-oss-120b, TP8): 5,024 page sets joined
across the 8 ranks, 5,024 equal, 0 mismatched (pushes: 2,400 FULL and 2,400
SWA; recalls: 112 FULL and 112 SWA).

Greedy-output comparisons are not usable as a correctness oracle on this
engine: with another request in flight, outputs diverge from the quiet
reference in a fixed pattern (fp8 KV, batch-dependent numerics) even for
plain P/D probes that never use the feature; a probe-free single-request
integrity run is recorded separately: with no other request in flight
(`victim_integrity.py --probes 0 --concurrency 1`, 12 sessions of 128k+8k,
8 of them recalled from decode RAM with up to 139k tokens landing in the
prefill's RAM), the greedy outputs after recall equal the recompute after a
flush exactly for all 12 sessions (64 of 64 tokens each).

## Unified KV pool compatibility (branch `pd-victim-unified-pool`)

The spill feature was merged with the unified KV pool PRs (#1002, #1296) on a
separate fork branch and run live on a 1P/1D pair with `--enable-unified-memory`
on both roles. Two incompatibilities, both fixed on that branch:

| # | Symptom | Cause | Fix |
|---|---|---|---|
| U1 | Every push declined; `Cannot register victim: 'TpuRaidenUnifiedHostKVCache' object has no attribute 'transfer'` | The unified host pools are facades over one shared raiden host pool and carry no transfer object | The facade exposes the shared pool's `transfer` (one-group sliding-window layouts; multi-group page expansion is not handled) |
| U2 | Every hybrid push declined; `NotifyForRead rejected duplicate uuid ... a read is still registered` | A hybrid victim's FULL and SWA reads register on the same manager under one uuid | The SWA read derives its own uuid from the push's, on both roles |

With both fixes (run `unikv4_after_1`, gpt-oss-120b, 128k+8k, caches wiped
before each point, table in `results/compare_table_unified_after.md`): 590
pushes started, 579 stored and landed, 65 recalls (6.7M tokens), no engine
errors on either role across four points:

| Point | Prefill hit before -> after | TTFT p50 | Total tok/s |
|---|---|---|---|
| static 12 docs x 3 | 35.6% -> 62.5% | 9.6 s -> 3.2 s (3.02x) | 31,181 -> 35,485 (1.14x) |
| static 24 docs x 3 | 14.7% -> 58.1% | 13.1 s -> 6.2 s (2.11x) | 25,856 -> 35,637 (1.38x) |
| recall 12 sessions | 0% -> 93.4% | 20.6 s -> 1.5 s (14.05x) | 20,403 -> 52,447 (2.57x) |
| recall 24 sessions | 0% -> 94.4% | 20.4 s -> 1.6 s (12.57x) | 21,229 -> 52,914 (2.49x) | The unified pool also changes the
baseline: its shared HBM pool holds more prefixes, so the 12-doc point reaches
60% hit even with the pushes declined.
