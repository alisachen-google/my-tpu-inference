## What it does

Moving KV bytes is insufficient when another component associates per-page metadata with those bytes, such as integrity tags. A recall into a reused host slot must receive the transferred page's tag, rather than keep the tag for the slot's previous contents.

The PR adds `register_host_page_metadata(pool, export=..., restore=...)`. An owner exports one opaque byte string per page; the receiver restores those strings under the destination's page IDs. FULL and SWA use separate lists and pools. This is metadata transport infrastructure, **not an integrity checker**: it does not calculate checksums or verify bytes itself.

| Stage | Behavior added |
| --- | --- |
| Prefill spills a pinned prefix | Snapshot the source page tags before native registration; include them in `VictimPush`. |
| Decode finishes receiving | Restore tags after native completion and before radix-tree insertion; all ranks reject if any restore fails. |
| Decode offers the cached prefix back | Export the requested FULL slice and complete offered SWA tail into `PrefixReady`. |
| Prefill finishes recalling | Restore tags onto the new page IDs before publishing the recalled host prefix. |
| No codec on Decode | Retain opaque tags in a page-indexed table. |
| No codec on Prefill | Discard incoming tags, because ordinary local backups can overwrite the slots. |

Codec registration uses a weak-key pool registry and is looked up at operation time, so the owner can register after channel construction. The fallback table is bounded in **entry count** by pool pages; payload byte size is not bounded by this module. Empty metadata lists are omitted from wire messages.

## F1 — P1 reliability: metadata export failure skips the recall refusal

**Location:** [`dram_offload_channel.py:522–523`](https://github.com/sgl-project/sglang-torchtpu/blob/49561a1503a7fe4059180571c89f1ed1cb3fe4ec/sglang_tpu/disaggregation/raiden/dram_offload_channel.py#L522-L523).

**Trigger:** a codec registered on Decode raises while exporting a pinned source, or returns a nonempty row list with the wrong length. `HostPageMetadata.export` then raises directly or through `_validate`.

**Consequence:** `_register_pull_locked` propagates the exception through `_on_prefix_pull` before its `PrefixReady` send. The listener catches and logs the error but does not answer. Prefill sees neither a ready registration nor an explicit refusal, so the recall keeps the room in Bootstrapping until the configured bootstrap timeout allows recomputation. One affected rank can delay the common decision. This is bounded fallback latency, not a demonstrated permanent deadlock or premature page release.

**Evidence:** [probe_pr2235_metadata.py](../../tests/pd_victim_review/probe_pr2235_metadata.py) executes the actual `_on_prefix_pull` and `_register_pull_locked` methods with simulated wire/native boundaries. Both an exporter exception and a wrong row count produce **zero READY replies and zero native registrations**, with an exception escaping. A normal exporter produces one registration and one READY. The downstream behavior is explicit in [`_local_recall_flags`](https://github.com/sgl-project/sglang-torchtpu/blob/49561a1503a7fe4059180571c89f1ed1cb3fe4ec/sglang_tpu/disaggregation/decode_dram_offload/prefill_dram_prefix_puller.py#L194-L208), [`prefix_pull_open_locked`](https://github.com/sgl-project/sglang-torchtpu/blob/49561a1503a7fe4059180571c89f1ed1cb3fe4ec/sglang_tpu/disaggregation/raiden/dram_offload_channel.py#L368-L385), and [listener error handling](https://github.com/sgl-project/sglang-torchtpu/blob/49561a1503a7fe4059180571c89f1ed1cb3fe4ec/sglang_tpu/disaggregation/raiden/conn.py#L1285-L1289).

**Fix:** catch export/validation failures before registering either source, log the failure, and return an empty `PrefixRegistration()` so the caller sends an immediate refusal. Add tests for FULL and SWA exporter failures, malformed row counts, and successful refusal delivery. Do not add a distributed collective inside this asynchronous listener handler; each rank can send its refusal and the existing Prefill agreement handles it.

## Verified non-issues and design boundaries

- **Publication order:** both receive paths restore after read completion and before tree insertion. Restore failure is agreed across ranks before a prefix can become visible; settled landing allocations follow the existing discard path.
- **Pins and page remapping:** spill metadata is captured after the host path is pinned. Recall sources are pinned by the offerer before the listener exports them. Rows follow the requested page order and are restored using destination page IDs, not sender IDs.
- **No added device synchronization in this module:** the table and wire operations use CPU lists/bytes. A codec may itself wait for a seal, so the callback cost and execution thread still need documentation and measurement.
- **Full-only operation:** empty SWA requests short-circuit before accessing an absent SWA pool. Missing metadata is passed to an installed owner, whose restore callback is responsible for rejecting it or clearing stale state.
- **Plugin direction:** all production additions remain in `sglang_tpu/`. No new TPU import or conditional is added to shared SGLang core.

## Manual review points

**Metadata lifetime outside victim insertion.** An existing automated comment claims stale Decode rows become recallable after ordinary Decode write-back. The fallback table does indeed retain a row after a page is freed, but the feature's [`_decode_add`](https://github.com/sgl-project/sglang-torchtpu/blob/49561a1503a7fe4059180571c89f1ed1cb3fe4ec/sglang_tpu/disaggregation/decode_dram_offload/dram_offload_hooks.py#L156-L161) marks served requests `skip_radix_cache_insert=True`; the intended persistent Decode cache consists of pushed victims. Every successful new victim restores or clears its assigned rows before insertion. Failed landings are not published, and host retraction backups are operation-owned rather than inserted by `backup_kv_cache`. I did **not establish a reachable stale-tag recall** in this supported flow, so I do not count the comment as a second confirmed defect. Before allowing another producer to populate recallable Decode host nodes, add an allocation-generation/invalidation contract and an integration test for that producer. Likewise, codec owners must handle their own ordinary overwrite/reset lifecycle.

**Mixed versions.** `WireMessage` rejects unknown fields. Nonempty new metadata fields therefore require upgraded peers on both sides; the PR description acknowledges there is no capability negotiation. Empty defaults preserve the old payload shape. Treat coordinated rollout as an explicit limitation, and add mixed-version serialization tests before claiming rolling-upgrade support.
