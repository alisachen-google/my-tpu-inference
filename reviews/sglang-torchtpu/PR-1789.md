**Recommendation: request changes.** Fix the device-source lifetime gap and reject or implement draft-sidecar transfers before merging. The primary host FULL/SWA ownership paths have substantial passing CPU coverage, but the probes below reproduce five gaps at this exact head.

## Motivation and solution

Prefill can exhaust its local host cache while Decode has spare DRAM. Prefill registers cold host-backed branches; Decode pulls their FULL KV and ending sliding-window KV into its host pools. The radix tree publishes the branch after distributed completion agreement. A later Prefill miss recalls it directly into Prefill DRAM, and normal admission performs the H2D load. Decode stores pushed victims instead of retaining all its own generation requests.

The umbrella flag enables spill, reverse prefix exchange and hybrid host-window policy. Device-prefix recall is also supported independently through the component flags; that separate configuration is affected by F1.

The main design concern is that component completeness and asynchronous ownership are spread across hardcoded FULL/SWA transfer loops, per-room protocol tables, tree pins, weak registries and global lifecycle wrappers. F1 and F2 show why both the complete pool set and native ownership need explicit contracts.

## Findings ordered by severity

Severity follows the repository guidance: P0 identifies a functional or ownership merge blocker; P1 identifies a reachable compatibility, configuration, retention or performance problem. Evidence below distinguishes real CPU cache/protocol behavior from simulated native work.

### F1 P0 correctness and ownership Device recall releases active sources

**Location:** [decode.py:2882–2886 and 2952–2956](https://github.com/sgl-project/sglang-torchtpu/blob/c910830c0e5962ec07f215ed1fec814e9b5dc323/python/sglang/srt/disaggregation/decode.py#L2882-L2886); [receiver.py:1729–1731](https://github.com/sgl-project/sglang-torchtpu/blob/c910830c0e5962ec07f215ed1fec814e9b5dc323/sglang_tpu/disaggregation/raiden/receiver.py#L1729-L1731).

With prefix pull enabled and victim push disabled, Prefill can time out a reverse read and compute the prompt while native work still owns the reverse source. Forward receive completion is sufficient for `RaidenKVReceiver.poll()` to return success. Queue exit releases any hybrid `prefix_offer_lock` without waiting for the reverse read; full-only offers rely on the ordinary request lock. Once the normal Decode request finishes and releases its own lock, cache eviction can recycle the source device pages. On hybrid models, the ordinary request lock can also stop before the deeper offered window (`decode.py:899–911`).

**Evidence:** the CPU source probe uses a real radix cache, allocator, receiver success poll and queue lock-release method with matching one-token pages. It manually acquires the normal request pin and follows the full-only policy of no extra offer pin. Forward success occurs with `room_has_active_io=True`. After queue exit and normal request completion, eviction removes the prefix and allocation reuses all eight source slots while that flag remains true. The native read is simulated as pending: this establishes missing source protection, not corrupted bytes on TPU. Delayed native source D2H is dangerous; a network send that has already staged every source byte may happen to be harmless.

**Change:** retain source ownership independently of queue membership. Defer source-pin release until all ranks observe native terminal reports, including fallback and successful forward handoff. Reuse the contract already implemented for `HostPrefixSource`. A Python timeout cannot establish that a native source is reusable.

**Suggested inline comment:**

> Can the device source pin survive successful queue exit until the reverse reads settle? Prefill can abandon a pull and recompute, so forward receive success does not imply reverse source completion. After Decode finishes, the current path permits eviction/reallocation while `room_has_active_io` is still true. Please defer source release as the host-offer path does and cover delayed native completion.

### F2 P1 compatibility Host transfers omit required draft sidecars

**Location:** [pd_victim_push.py:362–375 and 705–731](https://github.com/sgl-project/sglang-torchtpu/blob/c910830c0e5962ec07f215ed1fec814e9b5dc323/sglang_tpu/pd_victim_push.py#L362-L375); [pd_host_prefix_recall.py:259–283](https://github.com/sgl-project/sglang-torchtpu/blob/c910830c0e5962ec07f215ed1fec814e9b5dc323/sglang_tpu/pd_host_prefix_recall.py#L259-L283).

Spill and host recall transfer only FULL and SWA. The hybrid host-cache validator nevertheless accepts EAGLE3 and DFlash-family sidecar configurations (`pd_decode_swa_hicache.py:192–199,300–302`). Ordinary load-back derives DRAFT/DRAFT_SWA reads from the anchor host slots without separate sidecar validity ([unified_radix_cache.py:1771–1773 and 1847–1886](https://github.com/sgl-project/sglang-torchtpu/blob/c910830c0e5962ec07f215ed1fec814e9b5dc323/python/sglang/srt/mem_cache/unified_radix_cache.py#L1771-L1773)). Publishing the target host entry therefore exposes draft slots this transfer never wrote.

**Evidence:** the sentinel probe inserts target values `123` while DRAFT slots remain `-777`, then runs the real `load_back` and `HostPoolGroup.resolve_host_transfers`. Admission returns true and requests all eight untouched DRAFT values. Device copies are simulated. This demonstrates stale draft input, not target-output corruption: speculative verification may reject bad proposals. The fused drafter waits for HiCache reload and consumes the cache rather than regenerating the missing prefix (`chain_draft_worker.py:166–179`).

**Change:** initially reject victim mode when required sidecars exist, or enumerate all required `HostPoolGroup` pools and transfer, validate, settle and publish them together. Test distinct DRAFT/DRAFT_SWA sentinels, shared-prefix deduplication and partial-sidecar failure.

**Suggested inline comment:**

> These loops move FULL/SWA only, but accepted speculative configurations have DRAFT/DRAFT_SWA sidecars. Load-back derives sidecar reads from the same host slots, so target-only insertion consumes untransferred draft bytes. Could victim mode reject sidecars until they are included in the transfer and publication contract?

### F3 P1 configuration Explicit false component flags are ignored

**Location:** [pd_spill_flags.py:25–30](https://github.com/sgl-project/sglang-torchtpu/blob/c910830c0e5962ec07f215ed1fec814e9b5dc323/sglang_tpu/pd_spill_flags.py#L25-L30).

The umbrella flag is ORed with each Boolean component. With umbrella=`1`, explicitly setting either victim push or prefix pull to `0` still enables it. This contradicts the module contract and README promise that explicitly set component values win, preventing selective rollback or the documented partial setup.

**Evidence:** actual `EnvBool` overrides mark both components explicitly set and false, while both resolver functions return true. Existing tests check explicit SWA window counts, not Boolean false overrides.

**Change:** use the component value when `is_set()` is true, otherwise apply the umbrella default. Cover unset/false/true for both umbrella states and validate dependent combinations after resolution.

**Suggested inline comment:**

> The OR means umbrella=1 overrides explicit component=0. Could this check `is_set()` before applying the umbrella default, as the window-count resolver does? Both Boolean flags need explicit-false tests to preserve the documented override contract.

### F4 P1 retention Late prefix failures survive room cleanup

**Location:** [conn.py:742–754 and 834–848](https://github.com/sgl-project/sglang-torchtpu/blob/c910830c0e5962ec07f215ed1fec814e9b5dc323/sglang_tpu/disaggregation/raiden/conn.py#L742-L754); [host reports at 604–613](https://github.com/sgl-project/sglang-torchtpu/blob/c910830c0e5962ec07f215ed1fec814e9b5dc323/sglang_tpu/disaggregation/raiden/conn.py#L604-L613).

Prefill can ask for registration, refuse destination allocation and compute normally. Decode then retires the room before the unused source registration expires. Its later failure adds `room#px` or `room#pxs` to `_native_failed`, but stale-prefix cleanup only visits `_completed_send`. No live room remains to clear the failure. Repeated fallback grows metadata and later set-union/room-cleanup work. Host-backed failures have the same retention; a late host success also waits for an unrelated device-engine event to invoke stale cleanup.

**Evidence:** clear a real manager room before its simulated source report and drain. `7#px` remains in `_native_failed` after source-lease settlement and another unrelated completion. Equivalent host failures remain; host success remains in `_completed_send` immediately after host drain.

**Change:** clean retired source terminal records after lease settlement in both report paths. Preserve records still needed by live receiver plans or zombie destinations; purging every prefix completion indiscriminately would break ownership tracking.

**Suggested inline comment:**

> This cleanup only visits successful sends. A source registration expiring after `clear_room` leaves its `#px` failure in `_native_failed` indefinitely. Could retired source failures be reaped after lease settlement and host drain run equivalent cleanup? Live receiver/zombie completion records still need their own ownership boundary.

### F5 P1 performance Host reclaim can refuse a landing with enough reclaimable RAM

**Location:** [pd_host_prefix_recall.py:67–87](https://github.com/sgl-project/sglang-torchtpu/blob/c910830c0e5962ec07f215ed1fec814e9b5dc323/sglang_tpu/pd_host_prefix_recall.py#L67-L87), allocation at `210–235`.

The oldest-first walk visits an older parent before its backed child and correctly skips it to preserve host-prefix closure. It reclaims the child but never revisits the now-eligible parent. The caller attempts allocation once and abandons the recall if that is insufficient. Shared-prefix chains can therefore fall back to recomputation despite enough duplicate storage to satisfy the landing.

**Evidence:** a real write-through tree has a 16-token parent and an 8-token child in a full 24-token host pool. Reclaiming 16 frees only the child’s eight and a 16-token landing fails. A second reclaim frees the parent and makes it fit. The existing chain test asks for eight and sixteen in separate calls, missing combined demand.

**Change:** use an eligible-tip worklist that reconsiders parents, or repeat until the target is met or no progress occurs. Preserve host-only-child and ancestor-closure guards. Test combined demand in one allocation.

**Suggested inline comment:**

> An older parent is skipped before its child is reclaimed, then never revisited. A landing larger than that child can fail despite enough duplicate RAM in the chain. Could newly eligible parents be reconsidered within the same reclaim, with a test requesting more than the first tip provides?

## Readability and refactoring across the code base

1. **Type the component set and native ownership.** Describe memory domain, pool identity, page range, native IDs and terminal state in transfer records. Derive sidecars from `HostPoolGroup`. Keep request progress separate from source/destination ownership. This addresses F1/F2 and removes repeated FULL/SWA loops across export, landing and recall.
2. **Replace related protocol tables with an exchange record.** `PrefillState`, `DecodeState`, sender, receiver and `clear_room` manually maintain matching dictionaries/sets. A typed per-room exchange plus independent native-ownership records makes retirement auditable and reduces omissions like F4. Preserve the existing state-lock boundary.
3. **Keep duplicate reclaim and its eviction invariant together.** The recall helper reaches private tree trackers/release methods while an eviction wrapper elsewhere protects the resulting tree. Give one tree-core operation responsibility for eligibility, host-prefix closure and later device eviction; share invariant tests with ordinary write-back reclaim.
4. **Use explicit cache lifecycle seams.** `pd_victim_push._patch_targets:1037–1053` wraps seven methods, including checkpoint, reset, private eviction and scheduler idleness. Ownership is difficult to follow across these wrappers and weak registries. Introduce checkpoint, quiescence/reset and deferred-transfer callbacks with no-op defaults. Split generic seams from the TPU implementation per migration guidance. The new backend factory/offer methods are useful precedent.
5. **Resolve and validate configuration at startup.** Validate role, tree implementation, required pools, speculative plan and native capabilities before requests. Decode currently discovers missing SWA host storage in `_decode_add` during request ingestion. Preserve the distinction between page-aligned transfer-window sizing and pool budgeting for unaligned ends; they intentionally differ by a possible page.

## Edge case coverage and suggested validation

Existing CPU coverage includes FULL/SWA partial starts, failed transfers, refusal, deduplication, admission pins, idle/reset, paused progress and rank-asymmetric cleanup. The notes-repo suite includes real two-rank Gloo agreement tests. All new feature test registrations are CPU-only; registered TPU/e2e tests do not enable these feature flags.

| Priority area | Missing case and required result |
| --- | --- |
| Source lifetime | Pending reverse read, Prefill fallback, forward success, short Decode finish and eviction pressure; source slots remain reserved until terminal completion on all ranks. |
| Pool completeness | Distinct FULL/SWA/DRAFT/DRAFT_SWA bytes; missing or failed required sidecar prevents publication or startup rejects the configuration. |
| Terminal cleanup | Host/device source success and failure before/after room retirement; table sizes return to baseline without a future unrelated transfer. |
| Host pressure | Old-parent/new-child chains requiring multiple tips and ancestors in one reclaim; retain local HBM hits and host-prefix closure. |
| Distributed progress | A 2×2 TP/CP mesh with staggered offers, partial starts, asymmetric completion and empty/paused queues; identical collective order across ranks. |
| Live round trip | Registered two-role spill → forced local eviction → host recall → admission; check every required pool and greedy output against recomputation. Test concurrent traffic separately from serial equivalence. |
| Fault recovery | Refusal, restart, last-request abort, pause/flush and stalled native sockets; preserve ownership, resume progress and restore capacity. |

Improve `_FakeHostPool` (`test_pd_victim_push.py:129–159`): allocation uses only a count and free subtracts a length. Non-LIFO frees can overlap live allocations, and wrong-page/double frees go undetected. A real free-list fake with ownership assertions and per-page sentinels would make interleaved cancellation/deduplication tests meaningful at the page level.

## Other suggestions and manual review

- Record an immutable tpu-sync Python/native commit or build ID and tested `torch_tpu` ABI. README calls a moving `ram2ram` branch “pinned”; check capabilities at startup to catch mismatched artifacts before registration.
- Clarify SWA-count semantics. Decode uses the count to size its host-window tier; Prefill uses a positive value to enable path-end backup while retaining ordinary HiCache sizing. Increasing it does not cap Prefill to that number of windows.
- Keep the native socket limitation explicit: session deadlines do not interrupt blocked I/O. The documented per-I/O knobs mitigate a stalled call but do not establish source/destination reusability. Verify fault recovery with the exact native build; non-draining work can exhaust the four in-flight slots.
- The PR reports CRC comparisons, serial greedy equivalence and performance gains. These are author-reported hardware results, not measurements rerun here. Retain the harness, exact native build and workload configuration for repeatable CI, particularly concurrent traffic and fallback faults.
- GitHub reported `mergeable=false` at review time. Rebase and rerun affected checks against the current base before merge; this is separate from the findings.

## Verified nonissues

- Shared core adds no TPU imports or new `is_tpu()` branches; backend base methods preserve no-op behavior. The TPU debt checker passes.
- Host offer withdrawal and source registration share the state lock. Host pins survive queue departure/room cleanup until native completion. F1 concerns the separate device-source path.
- FULL and ending SWA reads must settle on all ranks before host publication. Partial-start failures retain accepted native destinations; pending backups are excluded as sources.
- Offer initialization checks TP/CP/PP geometry (`receiver.py:1630–1645`): incompatible reverse offers are disabled and victim mode explicitly fails the request. This is not missing validation.
- Prefix-native failures are isolated from ordinary request failure so fallback remains possible. F4 concerns their terminal metadata retirement.
- Earlier notes describe idle/reset, abandoned-read and orphan-DONE defects at older commits. Their regressions pass at this head; they are not repeated as current findings.
